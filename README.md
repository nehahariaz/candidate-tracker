# Candidate Tracker

A starter candidate task dashboard built with Next.js, TypeScript, Tailwind CSS, the App Router, and npm.

The home page contains the Candidate Tasks title, a subtitle, an Add Candidate button, and To Do and Completed sections. Click **+ Add Candidate** to open a small form with Candidate Name and RQ Number fields. Submit with **Add Candidate** to add a candidate to To Do, or use **Cancel** to discard the form. You can add multiple candidates; both fields are required.

Candidates are saved in your existing Supabase `candidates` table. On page load, the app fetches rows where `status = todo`, oldest first. Submitting the form inserts only `candidate_name` and `rq_number`; Supabase supplies the default `status` of `todo` and the table's generated fields. The saved row appears in To Do after the request succeeds. Refreshing reloads saved candidates; unfinished form entries are still lost. The Completed section remains a placeholder. No authentication or AI features have been added.

Loading and saving failures show a simple error message. A failed save keeps the form entries for retrying. Submission is disabled while the initial list loads or a save is in progress.

## Set up Supabase

1. In the repository root (beside `package.json`), copy `.env.example` to a file named `.env.local`.
2. Fill in these two variables locally, without posting the values in chat:

   ```dotenv
   NEXT_PUBLIC_SUPABASE_URL=your-project-url
   NEXT_PUBLIC_SUPABASE_ANON_KEY=your-public-anon-or-publishable-key
   ```

3. In the Supabase dashboard, open your existing project:
   - Find **Project URL** in the project's **Connect** dialog or **Project Settings → Data API**.
   - Find the **Publishable key** (`sb_publishable_...`) under **Project Settings → API Keys**. It works in `NEXT_PUBLIC_SUPABASE_ANON_KEY` despite the variable's name. If using legacy keys, select the **anon / public** key under **Legacy API Keys** instead.
   - Never use the secret key, `service_role` key, database password, or database connection string.
4. Restart `npm run dev` after changing `.env.local`. For hosting, add the same variables in the hosting provider's environment settings, then rebuild/redeploy. Next.js includes `NEXT_PUBLIC_` values in the browser bundle at build time, so they are public, not secrets.

`.env.local` is excluded from Git. `.env.example` contains empty placeholders and can be committed.

### Table access

This browser client uses Supabase's unauthenticated `anon` database role. Your existing `public.candidates` table must allow the intended `SELECT` and `INSERT` operations through table grants and Row Level Security (RLS) policies. Returning a newly inserted row also needs a `SELECT` policy. The `status` default must be `todo`, and `id` and `created_at` must be generated by the table. No schema or policy changes are applied by this app.

Keep RLS enabled. Without authentication, anyone who can access the app and its public key has the same permissions. Policies that allow anonymous reads/inserts expose those permitted rows and operations to those visitors; this setup does not provide a private, user-specific candidate list. If requests fail, check the URL/key and table policies. A successful request blocked from seeing rows by a SELECT policy may return an empty list rather than an error.

The production build can run without Supabase values, but loading and saving require valid settings and table access. A build alone does not verify a live database connection.

## Preview the app

Install Node.js 22 or later (a current LTS version is recommended), then open a terminal in this project folder and run:

```bash
npm install
npm run dev
```

Open http://localhost:3000 in your browser. Keep the terminal running while previewing. Press Ctrl+C in the terminal to stop it.

Edit `app/page.tsx` and save to see home page changes automatically.

## Important files

- `app/page.tsx`: client component with the home page layout, candidate form, and Supabase loading/saving logic.
- `lib/supabase.ts`: reusable Supabase client using the public environment variables.
- `.env.example`: blank configuration template; copy to `.env.local` and supply your public project values.
- `app/layout.tsx`: shared page frame, browser tab title, and description.
- `app/globals.css`: global styles and Tailwind CSS import.
- `package.json`: dependencies and commands for running the project.
- `package-lock.json`: exact dependency versions for repeatable npm installs.
- `tsconfig.json`: TypeScript settings for checking code.
- `next.config.ts`: Next.js configuration.
- `postcss.config.mjs`: connects Tailwind CSS to the build process.
- `eslint.config.mjs`: rules that help catch common code problems.

The app uses Next.js’s supported Webpack option for development and builds.

## Check and build

```bash
npm run lint
npm run build
```

To preview the production build, run `npm start` after building and open http://localhost:3000.
